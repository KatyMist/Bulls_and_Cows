# Архитектура «Быки и коровы»

## Данные и границы ответственности

`src/core/` не импортирует DOM, часы, localStorage или UI. Секрет и попытки — строки, поэтому `0123` сохраняет начальный ноль. Перед сравнением цифры нормализуются через `toLowerCase()`. Контракт `evaluateGuess` — две валидные строки одинаковой длины без повторов; проверка пользовательского ввода выполняется до сравнения.

`Game` (`src/core/game.ts`) содержит `readonly` настройки, секрет, статус, массив истории, начало и конец раунда в миллисекундах. `Entry` хранит строку попытки и числа быков/коров. `submitGuess` возвращает новый объект и `[...game.history, entry]`. Старые записи сохраняют ссылки и значения. Неверная, повторная попытка или попытка после победы возвращает исходное состояние. Время передаётся аргументом; победа фиксирует `finishedAt` один раз. TypeScript readonly запрещает изменение на этапе компиляции, а тесты дополнительно замораживают входные данные.

Побочные эффекты сосредоточены в `src/main.ts` (DOM, Date.now, генератор случайности) и `src/storage.ts` (localStorage). Генератор с `Math.random` по умолчанию недетерминирован; при переданном детерминированном `random` он воспроизводим. Функция не изменяет внешние данные. Локальное удаление цифры из собственного массива в `generateSecret` не мутирует входы или игровое состояние.

## Алгоритмы и функциональные приёмы

- `createDigitValidator(base)` фиксирует алфавит в замыкании и возвращает предикат символа. Это каррированная форма проверки `(base, char) → boolean`. Предикат используется в `isValidGuess` и в обработчике `input` в `src/main.ts`.
- `generateSecret` создаёт доступный алфавит, выбирает индекс через внедрённый `random`, удаляет выбранный символ из локального массива. Каждый шаг выбирает только из оставшихся цифр; при равномерном random выбор без повторов равномерен. Начальный ноль разрешён.
- `evaluateGuess` строит `Set` цифр секрета, `filter` считает позиционные совпадения, `reduce` считает все совпавшие цифры. Коровы — все совпадения минус быки. Ручных циклов со счётчиками нет.
- `isValidGuess` проверяет длину, `every` с предикатом алфавита и размер `Set` нормализованных символов. `A` и `a` считаются одной цифрой.
- `countPossibleSecrets(l,b) = b × countPossibleSecrets(l−1,b−1)`, база рекурсии `l=0 → 1`. Ноль разрешён в первой позиции, поэтому отдельного вычитания нет. Внутренние шаги поддерживают основания 0–16, а интерфейс даёт только 2, 8, 10, 16. Максимальный результат для интерфейса `P(16,6)=5 765 760`, безопасный для number.
- `memoize` — функция высшего порядка: оборачивает вычисление и хранит значения в Map по ключу `length:base`. Кэш скрыт от вызывающего кода, входы и результаты не изменяются. `Map.has` позволяет кэшировать и нулевые результаты. Рекурсивные подзадачи также кэшируются.
- `rankRecords` сортирует копию массива по числу попыток, затем времени; берёт топ-10. Хранилище разделено по `base:length`. JSON проверяется через `isRecord`, повреждённые данные отбрасываются, ошибки доступа не ломают игру. При невозможности записи показано сообщение.

## Сложность

Пусть `n` — длина числа, `b` — размер алфавита. Оценки обобщённые, хотя в UI `n≤6`, `b≤16`. Операции Set/Map считаем ожидаемо O(1).

| Функция                | Время                                          | Дополнительная память                  | Обоснование                                                                                                           |
| ---------------------- | ---------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | O(b + n·b)                                     | O(b+n)                                 | Алфавит создаётся за O(b), каждый из n вызовов splice сдвигает до b элементов; результирующий массив длины n.         |
| `evaluateGuess`        | O(n)                                           | O(n)                                   | Нормализация, Set, filter и reduce проходят строки линейно.                                                           |
| `isValidGuess`         | O(n+b)                                         | O(n+b)                                 | Нормализация и Set длины n, создание алфавита предиката длины b, every длины n. Для фиксированного b — O(n).          |
| `countPossibleSecrets` | O(n) при первом вычислении; O(1) при повторном | O(n) стек и до O(n) новых записей кэша | Каждый шаг уменьшает длину на 1; готовая пара находится в Map. Общая память кэша O(K), где K — число сохранённых пар. |

Добавление попытки копирует историю за O(h), где h — число предыдущих попыток. Проверка дубликата — O(h·n). Это осознанный выбор простоты для небольшой игровой истории. Рекорды сортируются за O(r log r) на копии массива; обычно r≤11 перед ограничением.

## Чистый код

- Одна ответственность: сравнение — `evaluateGuess.ts`, генерация — `generateSecret.ts`, изменение раунда — `game.ts`, хранение — `storage.ts`, отображение — `main.ts`.
- Явные зависимости: `random` в `generateSecret`; `now` в `startGame`/`submitGuess`. Тестам не нужны реальные часы и случайность.
- DRY: алфавит и фабрика проверки централизованы в `createDigitValidator.ts`; ключ хранилища — `keyFor` в `storage.ts`; создание DOM — `el` в `main.ts`.
- Guard clauses: `submitGuess` сразу отсекает неверные переходы и повтор; `isRecord` отвергает неподходящий тип до чтения полей.
- Говорящие имена: `finishedAt`, `durationMs`, `secretDigits`, `rankRecords`; интерфейсы описывают данные без классов.
- Динамический контент создаётся через `createElement`, `textContent`, `append`, `replaceChildren`; innerHTML и insertAdjacentHTML отсутствуют.

## TDD и FIRST

Пять обязательных функций имеют по два отдельных коммита: `test:` добавляет тесты и заглушку, тесты запускаются и падают на утверждениях; следующий `feat:` реализует функцию, весь набор становится зелёным. Тесты изолированы, быстры, воспроизводимы и самопроверяемы. Генерация тестируется с внедрённым random, время раунда передаётся числом. Тесты localStorage подменяют глобальное хранилище и восстанавливают его после каждого теста.

`pre-commit` запускает только lint-staged (ESLint + Prettier); поэтому красный TDD-коммит разрешён. `pre-push` запускает npm test и блокирует отправку незавершённого красного этапа. Пустой набор допускается через `--passWithNoTests` согласно [документации Vitest](https://vitest.dev/guide/cli). Хуки настроены по [документации Husky](https://github.com/typicode/husky/blob/main/docs/get-started.md).
